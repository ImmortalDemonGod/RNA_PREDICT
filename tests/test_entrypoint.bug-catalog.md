## Code Summary

### Public interface
- Console-script entry point: `rna_predict` → `rna_predict.__main__:main` (`pyproject.toml:61`)
- Container default command: `CMD ["rna_predict"]` (`Containerfile:5`)
- `python -m rna_predict` also resolves to `rna_predict/__main__.py` (Python package `__main__` protocol)

### Load-bearing comments / invariants
- `pyproject.toml:61` is the authoritative declaration that `rna_predict.__main__.main` is the entry function. Any caller of the console script or `python -m rna_predict` depends on this module existing.

### IO boundaries
- Process startup: the installed `rna_predict` script is a wrapper generated by setuptools/pip that calls `rna_predict.__main__:main`. If that import fails, every invocation fails.
- Container: `Containerfile:5` `CMD ["rna_predict"]` relies on the same broken entry.

### Branching points
- Import success vs. `ModuleNotFoundError` — the only branch; there is no fallback.

### Type definitions / magic-string contracts
- `rna_predict.__main__:main` is a hard-coded string in `pyproject.toml:61`; setuptools interprets it as `<module>:<callable>`. No type annotation protects this.

### Existing tests
- No test in the repository exercises `rna_predict.__main__` import, the `rna_predict` console script, or `python -m rna_predict`. This gap is the reason the bug survived to production.

## Bug Catalog

### Bug 1 — `rna_predict/__main__.py` is missing: console-script crashes at import

**Failure mode:** Any invocation of the `rna_predict` console script (or `python -m rna_predict`) raises `ModuleNotFoundError: No module named 'rna_predict.__main__'` before executing a single line of application logic.

**Blast radius:** The container's default command (`CMD ["rna_predict"]`) is permanently broken; every containerised deployment crashes at startup. The installed `rna_predict` CLI command is permanently broken for every user who `pip install`s the package.

**Why it's plausible:** The `pyproject.toml:61` entry point was written or left pointing at `rna_predict.__main__:main` while the actual implementation lives in `rna_predict/main.py`. A rename or reorganisation moved the code without updating the entry point, or the `__main__.py` file was never created. `find . -name __main__.py` returns no results (confirmed).

**Test type:** Captured bug / contract pin — import the module directly; the test fails while the bug is present and passes once `rna_predict/__main__.py` exists.

**Self-critique:**
- Fails when the bug is present? ✓ `importlib.import_module("rna_predict.__main__")` raises `ModuleNotFoundError`.
- Passes under behavior-preserving refactor? ✓ Any restructuring that keeps `rna_predict/__main__.py:main` will pass.
- Tests observable behavior, not implementation? ✓ Tests the public import contract, not internals.
- Uses public interface? ✓ The module path is exactly what `pyproject.toml:61` declares.

### Bug 2 — `rna_predict.__main__.main` callable is absent: entry point symbol missing

**Failure mode:** Even if `rna_predict/__main__.py` existed without defining a `main()` function, setuptools would generate a script that does `from rna_predict.__main__ import main` and then calls it — raising `ImportError: cannot import name 'main'` or `AttributeError` at runtime.

**Blast radius:** Same as Bug 1 — every invocation of the console script or `python -m rna_predict` crashes before doing any work.

**Why it's plausible:** The file might be created with only `if __name__ == "__main__":` guard logic (as `rna_predict/main.py` currently has) without a top-level `main` symbol. The entry point string `rna_predict.__main__:main` requires an explicit module-level `main` callable.

**Test type:** Captured bug / contract pin — verify `hasattr(module, "main") and callable(module.main)` after successful import.

**Self-critique:**
- Fails when the bug is present? ✓ If `__main__.py` exists but has no `main`, `getattr(mod, "main", None)` is `None`.
- Passes under behavior-preserving refactor? ✓ Only checks that the symbol exists and is callable.
- Tests observable behavior? ✓ Tests the public callable contract.
- Uses public interface? ✓ Same entrypoint string as `pyproject.toml:61`.

### Bug 3 — `python -m rna_predict --help` crashes: package is not directly executable

**Failure mode:** `python -m rna_predict --help` exits non-zero with: `No module named rna_predict.__main__; 'rna_predict' is a package and cannot be directly executed`. This is a distinct failure mode from Bug 1: Python explicitly requires `rna_predict/__main__.py` to exist to support the `-m` invocation form, which is the idiomatic alternative to the console script.

**Blast radius:** Any CI step, Dockerfile `RUN` instruction, or user shell command using `python -m rna_predict` fails silently or loudly. The Containerfile `CMD ["rna_predict"]` ultimately resolves to the same path.

**Why it's plausible:** Companion to Bug 1 — the same missing file causes both the `rna_predict` console-script failure and the `python -m rna_predict` failure. Both entry forms depend on `rna_predict/__main__.py`.

**Test type:** Process integration test — `subprocess.run([sys.executable, "-m", "rna_predict", "--help"])` and assert `returncode == 0`. This is the integration layer: it exercises the full end-to-end invocation chain (interpreter → package entry → `__main__.py` → `main()`).

**Self-critique:**
- Fails when the bug is present? ✓ Confirmed: exits 1 with the error message above.
- Passes under behavior-preserving refactor? ✓ Only asserts exit code 0, not output format.
- Tests observable behavior? ✓ Tests the actual process exit code and invocation contract.
- Uses public interface? ✓ `python -m rna_predict` is a public invocation form.
